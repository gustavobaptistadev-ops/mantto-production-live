# ADR-0003 — Execução nativa no Windows (sem Docker); instalações no drive D:

## Status
ACCEPTED (instrução explícita do dono do projeto em 2026-10-08)

## Contexto
O briefing pedia containers (Docker). O dono definiu: usar serviços nativos do Windows e instalar tudo no drive D:. Docker não está instalado na máquina.

## Problema
Rodar API, PostgreSQL, Redis e worker localmente sem Docker, e manter o projeto portável.

## Alternativas
1. Docker/Compose — rejeitado pelo dono.
2. Serviços nativos Windows (PostgreSQL e Redis/Memurai instalados em D:) + venv Python + Node — escolhido.
3. WSL — não solicitado.

## Decisão
- Sem Dockerfile/compose no repositório. Remover artefatos Docker.
- Ferramentas em `D:\DEV\tools\`; dados/caches em `D:\DEV\mantto-data` e `D:\DEV\mantto-cache` (pip via `PIP_CACHE_DIR`, TEMP em D:).
- Scripts PowerShell em `scripts/windows/` para setup, start e stop.
- Redis não possui build oficial para Windows: usar Memurai (ou Redis portátil) em D:; a camada de fila deve depender só do protocolo Redis (`REDIS_URL`).
- Produção: deploy em serviço Windows (NSSM/Windows Service) ou, se mudar, Linux; CI continua em Linux (GitHub Actions), sem build de imagem.
- Regra para agentes: nunca instalar nada fora de D:; pedir confirmação se algo exigir C:.

## Consequências
+ Atende ao ambiente do dono.
- Menos paridade dev/prod; scanner de container removido do CI (substituído por pip-audit/npm audit).
- Requisitos de "Docker sobe" no critério de aceite são reinterpretados como "serviços nativos sobem via scripts" (ver DEFINITION_OF_DONE/SPEC).
